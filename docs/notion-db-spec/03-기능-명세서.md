# 03. 기능 명세서

## 명세 작성 형식

각 기능은 다음 항목으로 관리한다.

- **기능 ID**
- **기능명**
- **사용자**
- **Endpoint**
- **사전조건**
- **입력**
- **처리 과정**
- **성공 결과**
- **실패 조건**

---

## F-01 회원가입

| 항목 | 내용 |
|---|---|
| 사용자 | 비회원 |
| Endpoint | `POST /v1/auth/signup` |
| 입력 | 이메일, 비밀번호, 닉네임 |
| 사전조건 | 이메일과 닉네임이 사용 가능해야 함 |
| 성공 결과 | 사용자 생성 및 토큰 발급 |
| 실패 조건 | 중복, 비밀번호 정책 위반, 형식 오류 |

**처리 과정**

1. 요청값을 검증한다.
2. 이메일과 닉네임 중복을 확인한다.
3. 비밀번호를 단방향 해시한다.
4. 사용자를 생성한다.
5. Access Token과 Refresh Token을 발급한다.

---

## F-02 사진 업로드

| 항목 | 내용 |
|---|---|
| 사용자 | 로그인 사용자 |
| Endpoint | `POST /v1/photos` |
| Content-Type | `multipart/form-data` |
| 입력 | 이미지 파일 |
| 출력 | `photo_id`, `status` |
| 성공 상태 | `201 Created` |

**검증 항목**

- 지원 형식: JPEG, PNG, WEBP
- 최대 용량: 팀 합의 필요
- 확장자가 아닌 실제 MIME 타입 확인
- 이미지 디코딩 가능 여부 확인
- 필요 시 EXIF GPS 제거

**실패 조건**

| 오류 코드 | 의미 |
|---|---|
| `UNSUPPORTED_IMAGE_FORMAT` | 지원하지 않는 형식 |
| `IMAGE_TOO_LARGE` | 최대 용량 초과 |
| `INVALID_IMAGE` | 이미지 디코딩 실패 |
| `STORAGE_ERROR` | 파일 저장 실패 |

## F-03 AI 분석 요청

| 항목 | 내용 |
|---|---|
| Endpoint | `POST /v1/photos/{photo_id}/analyses` |
| 사전조건 | 사진이 존재하고 요청자의 소유여야 함 |
| 출력 | `job_id`, `status=PENDING` |
| 성공 상태 | `202 Accepted` |

**처리 과정**

1. 인증 사용자를 확인한다.
2. 사진 존재 여부와 소유권을 검사한다.
3. 중복 실행 중인 분석이 있는지 확인한다.
4. `analysis_jobs`를 `PENDING`으로 생성한다.
5. 작업 큐에 `job_id`를 등록한다.
6. 분석 완료를 기다리지 않고 응답한다.

---

## F-04 분석 상태 및 결과 조회

| 항목 | 내용 |
|---|---|
| Endpoint | `GET /v1/analysis-jobs/{job_id}` |
| 출력 | 작업 상태, 분석 결과 또는 오류 코드 |
| 권한 | 작업을 요청한 사진 소유자 |

**처리 중**

```json
{
  "job_id": "job-uuid",
  "status": "PROCESSING",
  "result": null
}
```

**완료**

```json
{
  "job_id": "job-uuid",
  "status": "COMPLETED",
  "result": {
    "analysis_id": "analysis-uuid",
    "primary_emotion": "CALM",
    "confidence": 0.82,
    "emotion_scores": {
      "CALM": 0.82,
      "JOY": 0.11,
      "SADNESS": 0.07
    },
    "model_name": "dalm-emotion",
    "model_version": "1.2.0"
  }
}
```

## F-05 분석 재시도

| 항목 | 내용 |
|---|---|
| Endpoint | `POST /v1/analysis-jobs/{job_id}/retry` |
| 사전조건 | `FAILED` 상태이며 재시도 가능한 오류 |
| 성공 결과 | `PENDING` 변경 및 큐 재등록 |
| 제한 | 최대 재시도 횟수 적용 |

**재시도 가능**

- `MODEL_TIMEOUT`
- `MODEL_SERVER_ERROR`
- `STORAGE_TEMPORARY_ERROR`

**재시도 불가**

- `INVALID_IMAGE`
- `UNSUPPORTED_IMAGE_FORMAT`
- `PHOTO_NOT_FOUND`

## F-06 게시물 작성

| 항목 | 내용 |
|---|---|
| Endpoint | `POST /v1/posts` |
| 입력 | 사진 ID, 분석 결과 ID, 본문, 공개 범위 |
| 사전조건 | 사진과 분석 결과가 요청자의 소유여야 함 |
| 성공 상태 | `201 Created` |

```json
{
  "photo_id": "photo-uuid",
  "analysis_result_id": "analysis-uuid",
  "content": "오늘의 순간을 기록했어요.",
  "visibility": "PUBLIC"
}
```

**검증 항목**

- `analysis_result_id`가 해당 사진의 결과인지 확인한다.
- 사용자가 사진의 소유자인지 확인한다.
- 사진이 삭제되거나 차단된 상태인지 확인한다.

## F-07 피드 조회

| 항목 | 내용 |
|---|---|
| Endpoint | `GET /v1/posts?cursor={cursor}&size=20` |
| 출력 | 게시물, 작성자, 이미지, 분석 결과, 좋아요·댓글 수 |
| 페이지네이션 | Cursor 방식 |

`created_at + id`를 커서로 사용하여 새 게시물이 추가될 때 발생할 수 있는 중복과 누락을 줄인다.

---

## F-08 좋아요

| 기능 | Endpoint |
|---|---|
| 좋아요 등록 | `POST /v1/posts/{post_id}/likes` |
| 좋아요 취소 | `DELETE /v1/posts/{post_id}/likes` |

- `post_id + user_id` 복합 PK로 중복을 방지한다.
- 동일한 요청이 반복되어도 결과가 같도록 멱등성을 보장한다.
- 게시물 작성자에게 DB 알림을 생성한다.

---

## F-09 댓글

| 기능 | Endpoint |
|---|---|
| 댓글 작성 | `POST /v1/posts/{post_id}/comments` |
| 댓글 조회 | `GET /v1/posts/{post_id}/comments` |
| 댓글 수정 | `PATCH /v1/comments/{comment_id}` |
| 댓글 삭제 | `DELETE /v1/comments/{comment_id}` |

- 수정과 삭제는 작성자만 가능하다.
- MVP에서는 대댓글 깊이를 1단계로 제한한다.
- 부모 댓글에 답글이 있으면 부모는 소프트 삭제한다.

## F-10 알림

| 기능 | Endpoint |
|---|---|
| 알림 목록 | `GET /v1/notifications` |
| 단건 읽음 | `PATCH /v1/notifications/{id}/read` |
| 전체 읽음 | `PATCH /v1/notifications/read-all` |
| 기기 등록 | `POST /v1/device-tokens` |

**알림 종류**

- `ANALYSIS_COMPLETED`
- `ANALYSIS_FAILED`
- `POST_LIKED`
- `COMMENT_CREATED`
- `FOLLOW_CREATED`

> DB 알림은 앱 내 기록이고 FCM은 기기 전달 수단이다. FCM 전송 실패가 DB 알림 삭제로 이어지면 안 된다.
