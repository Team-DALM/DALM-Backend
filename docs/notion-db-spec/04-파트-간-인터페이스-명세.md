# 04. 파트 간 인터페이스 명세

## 1. 인터페이스 원칙

> Flutter → Backend → AI 순서로 통신하며 Flutter와 AI는 직접 통신하지 않는다.

- Flutter는 REST API와 JWT를 사용한다.
- Backend는 AI에 사용자 토큰이나 사용자 개인정보를 전달하지 않는다.
- AI에는 추론에 필요한 작업 ID와 이미지 위치만 전달한다.
- AI 결과는 JSON 직렬화가 가능한 표준 타입으로 변환한다.
- PyTorch Tensor 또는 내부 Python 객체를 응답으로 사용하지 않는다.

---

## 2. Flutter ↔ Backend

### 사진 업로드

```http
POST /v1/photos
Authorization: Bearer {access_token}
Content-Type: multipart/form-data
```

```json
{
  "data": {
    "photo_id": "photo-uuid",
    "status": "UPLOADED"
  },
  "error": null
}
```

### 분석 요청

```http
POST /v1/photos/{photo_id}/analyses
Authorization: Bearer {access_token}
```

```json
{
  "data": {
    "job_id": "job-uuid",
    "status": "PENDING"
  },
  "error": null
}
```

### 분석 상태 조회

```http
GET /v1/analysis-jobs/{job_id}
Authorization: Bearer {access_token}
```

Flutter는 다음 중 하나를 적용한다.

1. 일정 간격으로 상태 조회
2. 푸시 알림 수신 후 상태 조회

MVP 권장 방식은 **푸시 알림 + 화면 진입 시 상태 조회**다.

## 3. Backend ↔ AI

### 작업 입력

```json
{
  "job_id": "job-uuid",
  "photo_id": "photo-uuid",
  "storage_key": "users/user-id/photos/photo-id.jpg",
  "model_name": "dalm-emotion",
  "model_version": "1.2.0"
}
```

### 성공 결과

```json
{
  "job_id": "job-uuid",
  "status": "COMPLETED",
  "primary_emotion": "CALM",
  "confidence": 0.82,
  "emotion_scores": {
    "CALM": 0.82,
    "JOY": 0.11,
    "SADNESS": 0.07
  },
  "model_name": "dalm-emotion",
  "model_version": "1.2.0",
  "processing_time_ms": 438
}
```

### 실패 결과

```json
{
  "job_id": "job-uuid",
  "status": "FAILED",
  "error_code": "INVALID_IMAGE",
  "retryable": false
}
```

### AI 파트와 합의할 항목

- [ ] 감정 라벨 목록과 표기법
- [ ] `confidence` 범위: `0.0~1.0`
- [ ] 모든 감정 점수 합계 처리 방식
- [ ] 지원 이미지 포맷
- [ ] 이미지 리사이즈 및 정규화 기준
- [ ] 추론 제한 시간
- [ ] 모델 버전 표기 방식
- [ ] 오류 코드와 재시도 가능 여부
- [ ] GPU/CPU 실행 환경

## 4. 공통 API 응답

### 성공

```json
{
  "data": {},
  "error": null
}
```

### 실패

```json
{
  "data": null,
  "error": {
    "code": "PHOTO_NOT_FOUND",
    "message": "사진을 찾을 수 없습니다.",
    "request_id": "request-uuid"
  }
}
```

내부 예외 메시지나 스택 트레이스는 클라이언트에 반환하지 않는다.

---

## 5. HTTP 상태 코드

| 코드 | 사용 상황 |
|---:|---|
| `200` | 조회·수정 성공 |
| `201` | 리소스 생성 성공 |
| `202` | 비동기 작업 접수 |
| `204` | 삭제 성공, 본문 없음 |
| `400` | 잘못된 요청 |
| `401` | 인증 실패 |
| `403` | 접근 권한 없음 |
| `404` | 대상 없음 |
| `409` | 중복 또는 상태 충돌 |
| `413` | 파일 크기 초과 |
| `422` | 입력값 검증 실패 |
| `500` | 내부 서버 오류 |

---

## 6. 공통 오류 코드

| 오류 코드 | HTTP | 설명 | 재시도 |
|---|---:|---|---:|
| `AUTHENTICATION_REQUIRED` | 401 | 인증 필요 | N |
| `ACCESS_DENIED` | 403 | 소유권 또는 권한 없음 | N |
| `PHOTO_NOT_FOUND` | 404 | 사진 없음 | N |
| `JOB_NOT_FOUND` | 404 | 분석 작업 없음 | N |
| `UNSUPPORTED_IMAGE_FORMAT` | 400 | 지원하지 않는 형식 | N |
| `IMAGE_TOO_LARGE` | 413 | 파일 용량 초과 | N |
| `INVALID_IMAGE` | 422 | 손상되거나 해석 불가능한 이미지 | N |
| `ANALYSIS_ALREADY_RUNNING` | 409 | 분석이 이미 실행 중 | N |
| `MODEL_TIMEOUT` | 500 | 추론 시간 초과 | Y |
| `MODEL_SERVER_ERROR` | 500 | AI 실행 오류 | Y |
| `STORAGE_TEMPORARY_ERROR` | 500 | 저장소 일시 오류 | Y |

---

## 7. 버전 관리

- API 경로는 `/v1`처럼 버전을 포함한다.
- AI 결과에는 모델 버전을 포함한다.
- 응답 필드를 제거하거나 의미를 바꿀 때 API 버전을 변경한다.
- 선택 필드 추가는 기존 클라이언트가 무시할 수 있도록 설계한다.
