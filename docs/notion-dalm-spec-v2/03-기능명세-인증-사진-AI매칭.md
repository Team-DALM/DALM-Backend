## PHOTO-03 사진 등록

| 항목 | 명세 |
|---|---|
| Endpoint | `POST /v1/photos` |
| Content-Type | `multipart/form-data` |
| 입력 | 4:5 이미지 |
| 출력 | `photo_id`, `VALIDATING` |
| 성공 HTTP | `202 Accepted` |

**Backend 처리**

1. JWT와 계정 상태 확인
2. 사용자 시간대 기준 오늘 활성 사진 확인
3. 파일 크기·MIME·디코딩·최소 해상도·4:5 비율 확인
4. EXIF GPS 제거
5. 중복 사진 checksum 확인
6. Storage 저장
7. Photo `VALIDATING` 생성
8. 적합성 검사 작업 등록

## AI-01 사진 적합성 검사

| 검사 | 거절 코드 |
|---|---|
| 과도한 흐림 | `TOO_BLURRY` |
| 과도한 어두움 | `TOO_DARK` |
| 스크린샷·메신저 캡처 | `SCREENSHOT` |
| 문서·글자 위주 | `TEXT_DOMINANT` |
| QR·바코드 | `QR_OR_BARCODE` |
| 신분증·카드 등 민감정보 | `SENSITIVE_INFORMATION` |
| 성적·폭력적 콘텐츠 | `SEXUAL_OR_VIOLENT` |
| 광고·홍보물 | `ADVERTISEMENT` |
| 기존 등록 사진과 동일 | `DUPLICATE_PHOTO` |

### 통과

- Photo를 `SEARCHING`으로 변경
- `search_expires_at = registered_at + 7일`
- 특징 추출과 후보 탐색 시작
- 검사 완료 알림 생성

### 거절

- Photo를 `REJECTED`로 변경
- 구체적인 대표 거절 사유 한 개 반환
- 당일 새 사진 등록 허용

### 시스템 장애

- 정책 거절과 구분한다.
- 지정 횟수만큼 자동 재시도한다.
- 최종 실패 시 사용자에게 일시 오류로 안내한다.

## MATCH-01 후보 탐색

| 항목 | 명세 |
|---|---|
| 대상 기간 | 현재 시각 기준 탐색 기간이 남은 최근 7일 사진 |
| 대상 상태 | `SEARCHING` |
| 제외 | 동일 사용자, 차단 관계, 매칭 완료, 삭제, 기간 만료 |
| 검색 | 요소별 임베딩 기반 상위 K개 |
| 재정렬 | 요소별 점수와 학습 가중치로 최종 점수 계산 |
| 하한 조건 | 장면·의미 점수가 최소 기준 미만이면 제외 |

새 사진이 들어올 때 기존 `SEARCHING` 사진도 후보가 되므로 과거 사진과 새 사진을 양방향으로 비교할 수 있다.

## MATCH-02 매칭 확정

| 항목 | 명세 |
|---|---|
| 조건 | 최종 점수가 기준 이상인 최상위 후보 |
| 결과 | Match 1건 생성, 두 Photo를 `MATCHED` 처리 |
| 알림 | 양쪽 사용자에게 앱 내 알림과 푸시 |
| 저장 | 요소별 점수, 최종 점수, 설명, 모델 버전 |

### 동시성 처리

1. 두 사진 ID를 정렬한다.
2. 동일한 순서로 두 Photo 행을 `SELECT ... FOR UPDATE` 잠근다.
3. 둘 다 여전히 `SEARCHING`인지 확인한다.
4. 차단 관계와 탐색 만료를 다시 확인한다.
5. Match와 MatchParticipant를 생성한다.
6. 두 Photo를 `MATCHED`로 변경한다.
7. 한 트랜잭션으로 커밋한다.

한 단계라도 실패하면 전체 롤백한다.

## PHOTO-04 매칭 전 사진 삭제

| 항목 | 명세 |
|---|---|
| Endpoint | `DELETE /v1/photos/{photo_id}` |
| 허용 상태 | `SEARCHING`, 필요 시 `EXPIRED` |
| 처리 | 상태 DELETED, 벡터 제거, 진행 작업 취소, 원본·썸네일 삭제 |
| 결과 | 당일 새 사진 등록 가능 |
| 금지 | `MATCHED` 사진에 동일 삭제 API 사용 불가 |

삭제와 매칭 확정이 동시에 실행되면 Photo 행 잠금을 먼저 획득한 트랜잭션만 성공한다.
